MkDocsPathFileTypeInspection

class MkDocsPathFileTypeInspection : LocalInspectionTool

Reports a path value of an MkDocs configuration file naming a file of a type the key cannot use.

Some keys read a path and do something specific with what they find: extra_css writes a <link> into every page, extra_javascript a <script>, and theme.logo and theme.favicon end up in an <img> and in the icon of the browser tab. A Markdown page behind any of them is a file that exists, so the references resolve it happily and nothing is marked — while the built site silently loads a page as a style sheet. That gap is what this inspection closes.

It is a separate check rather than one more entry of the path check next to the references, because it is the one finding whose answer is a matter of taste in the corners: a project generating its style sheet into a file without the usual extension is doing something unusual, not something broken, and should be able to switch the report off without losing the character check of the same value.

Only a value that has an extension is judged. A value without one is left alone on purpose: below theme.logo and theme.favicon the Material theme accepts the name of one of its own icons — material/library — which is no path at all, and reporting it would mark a perfectly ordinary configuration.
